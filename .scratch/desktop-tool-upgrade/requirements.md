## 已核对的实现事实

- 工作区开始时 `git status --short` 为空。
- 项目已有共用 `IDesktopWorkspace` 业务接口、真实文件检查与独立 Windows 会话验收；本次升级沿用这些边界。
- `ShellIcons.Read` 当前请求 Shell 覆盖图标，并在大尺寸系统图像列表分支再次应用覆盖索引；去掉箭头需覆盖两个读取分支。
- `Runtime.Open` 已有真实路径打开逻辑：目录使用 Explorer，文件使用 `UseShellExecute = true`。存在该方法不能证明用户的双击事件能够到达它。
- 结果提示目前混用 `MessageBox`、操作结果窗口和托盘提示。新建失败、设置应用结果、打开失败等仍存在弹窗；需统一梳理结果通知入口。
- `StyleDialog` 当前标题为 `<名称> · 外观`，透明度标签包含“· 实时预览”，端点标签用固定空格定位。
- `SettingsWindow` 当前使用连续堆叠的控件布局；需要按功能重新组织，并保留存储、自启、恢复和桌面 Folder 的现有能力。

## 已确认的交互决策

### Q1：释放落点冲突与展开腾挪

当前已向用户询问以下选择：

1. 推荐：只移动当前 Folder，释放时寻找鼠标落点附近最近的可用位置。展开空间不足时优先移动当前 Folder；整个可用区域仍容纳不下时保留折叠并给出非阻塞提示。
2. 允许自动挪动其他 Folder，为当前 Folder 腾出位置。

已确认：用户选择第 1 项。释放和展开仅调整当前 Folder，其他 Folder 保持位置；无可行位置时恢复原位或保留折叠，并提示原因。

### Q2：内部拖动与自定义排序

当前已向用户询问以下选择：

1. 推荐：在同一个 Folder 中拖到新的插入位置后自动切换为自定义排序；拖到其他 Folder、桌面或 Explorer 继续执行真实文件移动。
2. 先显式选择“自定义排序”，才允许内部拖动重排。

已确认：用户选择第 1 项。内部拖动自动切换自定义排序，跨 Folder／桌面／Explorer 的拖动仍执行文件移动。

### Q3：原生菜单呈现

已确认：用户接受 Windows 原生传统完整菜单（Windows 11 的“显示更多选项”形式），包含系统和已安装程序提供的菜单项。

## 只读调查结论

- `FolderContents` 已监听双击，并根据项目实际路径调用打开逻辑；`FileDrag` 在已选中项目的 Preview 左键按下阶段标记事件已处理。后者需要纳入准确复现，但尚不能作为根因结论。
- 旧内容验收直接 `RaiseEvent(MouseDoubleClickEvent)`，验证了实际快捷方式目标和 Explorer 目录打开，但跳过真实输入及 Preview 事件路由；本次需补物理双击输入的回归。
- 内容项目未提供自己的上下文菜单或 Shell 原生菜单调用；当前 Folder 菜单设置于整个窗口，与右键反馈一致。
- 当前仅支持 ListBox 扩展选择，未实现空白处矩形框选；列表小图标、网格大图标尺寸固定；内容固定按不区分大小写的名称升序排列。
- 当前拖动禁止穿越其他 Folder，展开优先固定自身、挪动其他 Folder；这与原规格一致。本次用户已经明确改变这两条规则，新规格将覆盖相应旧验收期望，保留旧规格作为历史依据。
- 头部高度已有持久字段，当前范围 42—82 DIP；展开时右下角仅调整宽度与展示部分高度。分隔线新增独立头部调高入口，展示部分高度保持不变。

## 设计讨论记录

以下保留讨论时提出的方案；用户现已确认正式规格，最终规则与验收以 `spec.md` 为准：

- 每个 Folder 独立保存查看方式、图标尺寸、排序方式和自定义顺序，重启恢复。
- 网格与列表提供小、中、大、超大四档图标；尺寸按 DPI 缩放，使用足够分辨率的图像。
- 框选从展示部分空白处开始，提供可见选区，兼容 Ctrl／Shift、多选拖动和滚动。
- 原生菜单针对实际选中的文件或子目录；右键未选中项目先调整选择。头部和展示部分空白处保留 Folder 管理入口。
- 隐藏 `.lnk` 后缀仅影响显示；箭头变化仅影响本程序内图标，保留实际路径的关联图标和其他适用标记。
- 操作结果按批次汇总为一条 Windows 通知，避免批量操作逐项刷屏；开关持久化，默认开启。关闭提示时，必要的恢复状态与错误详情仍能在设置内查看。
- 文件移动的冲突询问、删除方式选择及名称输入继续使用交互窗口；已完成操作的纯结果窗口自动结束。
- 设置采用侧栏与内容区，建议分为“通用”“桌面 Folder”“存储”“通知”“恢复与状态”“关于”。
- 分隔线调整头部高度时保留展示部分高度，最终整体布局遵守屏幕工作区和无重叠约束；设置最小／最大高度并在重启恢复。
- 托盘图标先检查现有 ICO 各分辨率的有效图形面积；正式规格确定保留四套方案并统一减少留白。

## 调查与验收边界

- 双击根因尚未确认；先运行能验证用户准确症状的检查，避免把“已有打开方法”当作问题已经解决。
- 新版读取 1.0.0 的状态时应补齐新增字段默认值，并保留内容目录、归属标识、待恢复意图和有效备份。
- 原生文件菜单通过 Shell 提供；实际 Windows 菜单呈现需在当前系统验证，不能仅以自制菜单外观宣称满足原生要求。
- 通知需在普通用户、无打包身份的自包含发布 EXE 中验证；通知中心投递、关闭开关、系统屏蔽通知和新版程序位置变化均需考虑。
- 几何预览不在鼠标移动期间读取目录或持久化；释放时提交最终布局，失败后恢复已提交位置。
- 真实会话检查使用隔离夹具，不以用户的正式文件充当移动、删除或启动样本。
- 现有 1.0.0 发布包作为问题基线，后续另行生成新版完整发布目录。

## 技术资料

- [SHGetFileInfoW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow)：覆盖图标、显示名称和系统图像列表读取标志。
- [IContextMenu](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-icontextmenu)：获取 Shell 对象的原生菜单及执行命令。
- [Windows 应用通知](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/)：WPF 桌面应用通知与交互。该资料说明 Windows App SDK 通知不支持提权应用，验收应匹配用户普通双击启动场景。
