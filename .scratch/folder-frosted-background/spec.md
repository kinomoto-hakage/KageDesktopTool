## 问题陈述（Problem Statement）

现有桌面 Folder 可设置背景颜色和透明度，但透出的背景仍然清晰。用户希望增加毛玻璃效果，使头部和展示部分在保留桌面背景观感的同时形成柔和的背景层，并继续清晰显示 Folder 名称、文件数、按钮、文件图标和文字。

用户需要逐 Folder 决定是否使用此效果，延续现有样式预览、应用、取消和重启恢复操作。环境无法提供效果或系统暂时限制透明效果时，需要明确反馈，并在条件恢复后自动恢复用户选择。

## 解决方案（Solution）

在现有“样式…”窗口增加“启用毛玻璃”开关，每个 Folder 独立保存。新建 Folder 默认关闭；旧配置缺少该设置时也按关闭处理，保留已有外观。

开启后，对 Folder 背后的实际实时画面进行模糊，包括动态壁纸和桌面图标，再叠加现有背景颜色。拖动时效果随位置更新，失去焦点后持续显示。效果统一覆盖头部和展开后的展示部分，折叠时仅保留头部效果，适配四向头部并限制在 Folder 圆角边界内。Folder 自身的文字、图标和交互控件保持清晰。

首版采用一种固定模糊强度，具体强度通过真实桌面视觉验收确定。现有背景透明度控制颜色叠加的浓淡：透明度为 100% 时去掉颜色叠加但保留背景模糊；透明度为 0% 时背景颜色完全遮住后方画面，模糊不可见。关闭毛玻璃后按既有背景颜色和透明度显示。

开关与颜色、透明度共同参与现有样式草稿事务：修改立即预览，应用成功后保存，取消、Esc 或关闭恢复打开前的设置。预览不提前写入正式配置。

当前环境不支持效果，或 Windows 关闭透明效果、开启高对比度模式、进入省电模式时，暂停毛玻璃并回退到既有颜色与透明度背景。保存的启用状态保持不变，样式窗口显示不可用或暂停原因；限制解除且环境可用后自动恢复，无需再次操作开关。

## 用户故事（User Stories）

1. 作为用户，我希望在“样式…”窗口找到“启用毛玻璃”开关，以便从现有外观入口设置效果。
2. 作为用户，我希望每个 Folder 独立设置毛玻璃，以便按不同桌面区域选择外观。
3. 作为用户，我希望启用一个 Folder 时其他 Folder 保持原设置，以便逐个调整。
4. 作为用户，我希望新建 Folder 默认关闭毛玻璃，以便明确选择后再启用。
5. 作为已有用户，我希望升级后原有 Folder 默认关闭毛玻璃，以便保留之前的桌面观感。
6. 作为用户，我希望已应用的开关状态在程序重启后恢复，以便无需重复设置。
7. 作为用户，我希望关闭毛玻璃后恢复现有颜色与透明度效果，以便随时切换回熟悉的外观。
8. 作为用户，我希望开启后模糊的是 Folder 背后的实际画面，以便效果与真实桌面一致。
9. 作为用户，我希望静态壁纸在 Folder 内呈现对应区域的模糊，以便看到位置正确的背景。
10. 作为用户，我希望动态壁纸变化时毛玻璃背景同步更新，以便看到持续变化的画面。
11. 作为用户，我希望 Folder 背后的桌面图标也进入模糊背景，以便整个后方画面具有一致效果。
12. 作为用户，我希望拖动 Folder 时模糊区域随当前位置更新，以便背景不会停留在拖动前的位置。
13. 作为用户，我希望停止拖动后显示最终位置的背景，以便效果与 Folder 的落点一致。
14. 作为用户，我希望切换到其他应用后 Folder 仍显示毛玻璃，以便桌面外观不依赖焦点。
15. 作为用户，我希望首版使用一种统一的模糊强度，以便通过一个开关即可使用效果。
16. 作为用户，我希望背景细节变得柔和且仍能感知后方色彩，以便获得毛玻璃观感。
17. 作为用户，我希望头部使用毛玻璃背景，以便入口外观与整个 Folder 一致。
18. 作为用户，我希望展开后的展示部分使用相同效果，以便形成连续的背景。
19. 作为用户，我希望折叠时只在头部保留效果，以便收起的展示部分不残留背景。
20. 作为用户，我希望上、下、左、右头部都正确显示效果，以便现有方向设置继续可用。
21. 作为用户，我希望头部与展示部分交界处没有重复模糊或明显接缝，以便背景连续。
22. 作为用户，我希望模糊被限制在 Folder 的圆角边界内，以便边界外的桌面保持原样。
23. 作为用户，我希望拖动及调整尺寸后效果边界与 Folder 边界一致，以便不产生残留或错位。
24. 作为用户，我希望 Folder 名称、文件数与按钮保持清晰，以便继续辨认并操作入口。
25. 作为用户，我希望文件图标和文件名保持清晰且不受背景透明度影响，以便阅读和识别内容。
26. 作为用户，我希望列表、网格、滚动条与选中名称全文保持原有操作，以便设置背景后继续正常浏览。
27. 作为用户，我希望现有背景颜色用于给毛玻璃着色，以便继续使用已选颜色。
28. 作为用户，我希望现有透明度滑块控制颜色叠加浓淡，以便无需学习另一套透明度设置。
29. 作为用户，我希望透明度为 100% 时颜色叠加消失而模糊仍在，以便使用不着色的毛玻璃。
30. 作为用户，我希望透明度为 0% 时背景颜色完全遮住后方画面，以便保持完全不透明的语义。
31. 作为用户，我希望中间透明度值连续改变着色浓淡，以便平滑调整背景。
32. 作为用户，我希望关闭和重新开启毛玻璃不会重置颜色与透明度，以便保留已调整的外观。
33. 作为用户，我希望切换开关立即在目标 Folder 上预览，以便在保存前判断效果。
34. 作为用户，我希望预览期间正式配置保持原值，以便预览不会提前成为保存结果。
35. 作为用户，我希望颜色、透明度和毛玻璃开关一起应用，以便保存一份完整样式。
36. 作为用户，我希望点击取消恢复打开前的样式，以便放弃本次修改。
37. 作为用户，我希望按 Esc 或关闭样式窗口也恢复原样，以便不同退出方式保持一致。
38. 作为用户，我希望保存失败后原正式设置仍有效，并能重试或取消，以便避免部分保存。
39. 作为用户，我希望后台刷新期间保持当前有效预览，以便外观不会在草稿和正式值间闪回。
40. 作为用户，我希望过期草稿不能覆盖后来保存的样式，以便保持最近有效设置。
41. 作为用户，我希望运行环境无法提供毛玻璃时仍显示现有颜色与透明度背景，以便 Folder 继续可用。
42. 作为用户，我希望环境不可用时保存的启用状态仍然保留，以便不会丢失选择。
43. 作为用户，我希望样式窗口提示“当前环境无法显示毛玻璃”，以便理解开关已启用但未显示效果的原因。
44. 作为用户，我希望 Windows 关闭透明效果时暂停毛玻璃，以便尊重系统设置。
45. 作为用户，我希望 Windows 开启高对比度模式时暂停毛玻璃，以便尊重系统设置。
46. 作为用户，我希望进入省电模式时暂停毛玻璃，以便尊重系统设置。
47. 作为用户，我希望样式窗口显示当前暂停原因，以便区分系统限制与环境不支持。
48. 作为用户，我希望限制解除且环境可用后自动恢复毛玻璃，以便无需重新切换开关。
49. 作为用户，我希望多个限制同时存在时，在全部限制解除后才恢复效果，以便不会提前恢复。
50. 作为用户，我希望本就关闭毛玻璃的 Folder 在环境恢复后仍保持关闭，以便系统变化不会改变选择。
51. 作为用户，我希望在暂停期间仍能应用启用状态、颜色和透明度，以便提前保存所需外观。
52. 作为用户，我希望环境在预览期间变化时，取消仍恢复原有开关，并按当前环境显示效果，以便取消不会撤销系统变化。
53. 作为用户，我希望 Explorer 重启并恢复桌面宿主后，已保存效果自动重建，以便继续看到正确背景。
54. 作为用户，我希望多个已启用 Folder 同时正常显示，以便整理整个桌面。
55. 作为用户，我希望毛玻璃不会改变 Folder 位置、尺寸或内容，以便背景设置不会干扰桌面整理。
56. 作为用户，我希望毛玻璃不会改变拖动、文件打开、原生菜单和文件移入移出行为，以便现有操作继续正常。
57. 作为用户，我希望显示器位置与 DPI 变化后，背景采样和圆角边界继续对齐，以便不同显示环境中效果正确。
58. 作为用户，我希望毛玻璃运行时桌面操作保持流畅，以便视觉效果不妨碍操作。

## 实现决策（Implementation Decisions）

### 业务状态与样式事务

- 延用 `IDesktopWorkspace`、`FolderRecord`、`AppearanceInteraction` 和现有样式保存边界；毛玻璃启用状态属于逐 Folder 的外观设置。
- 在持久化记录增加默认关闭的可选布尔设置。旧记录缺少字段时加载为关闭；保存、重启、记录复制、保留内容及相关恢复路径应完整保留该设置，不借此改变既有状态格式的其他含义。
- 将开关纳入草稿、有效性检查、预览合并、应用及取消路径。与颜色、透明度使用同一次保存，保存成功后再发布正式状态；失败保留原正式记录和可重试草稿。
- 后台刷新读取有效草稿；失效会话按既有保护处理。恢复锁定、根目录迁移和显示环境变化的保护继续适用，不通过新增开关绕过业务限制。
- 毛玻璃开关本身不触发布局变更；与其他样式一并编辑时继续沿用当前布局规则：只有位置拖动松手时寻找空位。背景效果不引入新的自动挪动规则。

### 背景绘制与平台能力

- 毛玻璃只作用于背景层，前景内容单独保持清晰。覆盖完整可见 Folder，并使用同一几何和圆角边界，避免头部与展示部分重复叠加。
- 背景来源必须对应当前位置背后的实际画面，包含动态壁纸和桌面图标；处理路径应排除 Folder 自身的前景和已绘制背景，避免将自身递归模糊造成重影。
- 拖动、尺寸调整、折叠／展开、方向变化、DPI 变化和宿主重建后，应更新效果的采样位置与覆盖范围。位置采用既有物理像素语义，尺寸采用 DIP，并沿用当前 DPI 换算。
- 颜色和透明度控制颜色叠加，不控制模糊强度。界面透明度与记录中的不透明度继续沿用现有反向关系；极值行为以用户故事 29、30 为准。
- 首版固定一种模糊强度。通过真实桌面验证后记录最终参数与视觉证据；本规格不预设模糊半径，不提供强度滑块。
- 业务层保存用户意图，平台层管理效果是否实际生效及原因。运行时不可用或暂停状态不写回为“关闭”，也不持久化为环境恢复后的强制限制。
- 平台实现集中在既有 Windows 桌面适配与运行时绘制边界，避免将系统 API 或绘制细节扩散到业务契约。若需要能力检测或通知接口，优先复用既有平台边界，本规格不预先固定未经验证的新接口。

### 运行时降级与恢复

- 当前有效状态由当前有效样式（编辑期间为有效草稿，否则为正式设置）、平台可用性和系统限制共同决定。关闭时显示原有背景；启用且可用且无限制时显示毛玻璃；启用但不可用或受限制时回退到原有背景。
- 系统透明效果关闭、高对比度开启、省电模式开启均阻止毛玻璃；多个限制叠加时，只有全部解除且平台可用才能恢复。焦点变化不属于暂停条件。
- 回退继续使用当前有效颜色与透明度。样式窗口的开关显示用户选择，并另行显示有效状态或暂停原因，不用临时回退覆盖开关值。
- 环境不支持时显示“当前环境无法显示毛玻璃”；系统限制时显示对应原因。多个原因的提示应足以解释剩余限制，具体排版与文案可按现有样式窗口确定。
- 环境变化会更新已显示效果和打开的样式窗口。取消只恢复外观草稿，不恢复过去的系统状态；应以恢复后的正式设置重新判断当前有效效果。
- 效果资源按 Folder 和宿主生命周期管理，关闭、删除、暂停或宿主丢失时及时释放；宿主可用后按当前设置重建。多个 Folder 不应相互覆盖状态或共用错误的采样位置。

### 技术可行性前置验证

- 现有 Folder 为透明 WPF 窗口，并挂接为 Explorer 桌面子窗口。普通顶层窗口的材质样例不足以证明该宿主结构可用。
- 实现前先在当前真实桌面宿主验证背景实时模糊、前景清晰、失去焦点后持续显示、透明度极值及圆角裁剪，再选定平台方案。验证使用隔离 Folder，避免改动用户内容和正式配置。
- 平台方案尚未选定。不得将尚未实测的系统 Acrylic、其他系统合成方案或背景采样方案描述为已经可用。
- 不可用时回退是运行时兼容策略；功能交付仍需要在声明支持毛玻璃的环境中提供真实效果证据。所有环境均只显示回退背景，不能满足毛玻璃功能的交付要求。

## 测试决策（Testing Decisions）

### 验证边界

- 主要业务边界为 `IDesktopWorkspace`，通过正式外观入口验证草稿、应用、取消、持久化、旧配置兼容、保存失败及并发保护，优先复用现有测试夹具，不为每个内部字段或绘制调用建立单独测试缝隙。
- Windows 绘制和系统环境行为通过正式桌面宿主与实际输入进行集成验收。平台状态决策可通过现有平台边界提供确定性环境轨迹，但实际合成能力、背景更新和系统设置响应必须有真实会话证据。
- 好的测试验证用户可见效果、正式状态、重启结果、真实内容和输入行为。记录中的开关值、API 返回成功、控件事件注入或单独的 WPF 离屏渲染不能替代实际桌面背景模糊证据。

### 既有验证模式

- 业务侧沿用 `AppearanceChecks` 的颜色／透明度输入、取消、失败重试、逐 Folder 保存和过期草稿模式，以及 `JsonWorkspaceStore` 的真实状态文件读写。
- 桌面侧沿用 `AppearanceChecks`、`FourWayInputChecks`、`StyleLayoutFeedbackChecks`、`DesktopRecoveryChecks` 的真实 Windows 鼠标／键盘输入、实际窗口边界、Explorer 生命周期和截图核对模式。
- 真实桌面输入检查串行执行，避免争抢焦点；隔离工作区使用随机真实目录、文件和快捷方式，记录内容字节与状态以验证背景修改没有损坏数据。

### 验收矩阵

| 范围 | 方法与观察结果 |
| --- | --- |
| 默认值与升级 | 加载真实旧状态，缺省字段为关闭；位置、尺寸、方向、颜色、透明度、查看方式、排序和内容保持原值。新建 Folder 也默认关闭。 |
| 独立保存 | 两个以上 Folder 分别设置，应用后检查实际状态并重启，目标设置恢复且其他 Folder 不变。 |
| 草稿事务 | 开关、颜色和透明度一起预览；正式状态未改；后台刷新保留有效预览；应用一次保存；取消、Esc、关闭恢复原值。 |
| 失败与保护 | 保存失败可重试或取消；过期会话不覆盖新样式；恢复锁定、迁移和显示变化沿用保护；并行布局或内容变化不被旧草稿覆盖。 |
| 真实背景 | 使用可辨识的高频静态图案、桌面图标和持续变化的背景，比较开关前后实际桌面截图；后方细节被模糊，颜色与位置对应，Folder 自身文字和图标保持清晰。 |
| 透明度极值 | 100% 透明仍有模糊且无颜色叠加；0% 透明由颜色完全覆盖；中间值连续调整着色；关闭效果恢复原有背景语义。 |
| 动态更新与焦点 | 背景变化时无需手动刷新；实际拖动期间与落点背景正确；切换应用后继续显示，无自身重影、长期冻结或重复模糊。 |
| 四向与圆角 | 上／下／左／右分别验证折叠、展开、方向切换和尺寸调整；交界连续，圆角外桌面不被改变，无背景残留或错误命中。 |
| 暂停与恢复 | 实际切换系统透明效果、高对比度和可触发的省电状态，检查回退、原因提示和自动恢复；多限制轨迹在全部解除后才恢复；开关关闭的 Folder 始终保持关闭。 |
| 预览期间环境变化 | 预览时进入或退出限制，按当前有效草稿更新；取消恢复原开关并根据当前环境重新计算效果；限制期间应用后重启保留用户意图。 |
| 平台不可用 | 验证能力不可用或效果资源失败时的原背景回退及原因提示；能力恢复后重建效果，用户启用状态不被覆盖。模拟结果与真实平台故障证据分别记录。 |
| 生命周期 | 程序重启与 Explorer 重启恢复后正确重建；关闭、删除、暂停及多次重建无旧效果残留，资源不持续增长。 |
| 交互回归 | 真实点击、拖动、缩放、选择、列表／网格、全文滚动、双击打开、原生右键菜单和文件移入移出继续正常；毛玻璃切换不改变布局和实际内容。 |
| 显示环境 | 业务轨迹覆盖负坐标及不同 DPI 的位置语义；真实硬件验收记录屏幕和缩放配置，多屏、混合 DPI、拔屏及系统缩放变化未覆盖项明确列出。 |
| 性能与视觉 | 记录代表性多个 Folder、动态背景和拖动场景的实际 CPU／GPU、资源与交互表现，并与关闭效果对照；固定强度的视觉证据需覆盖明暗背景、桌面图标和透明度极值。 |

### 交付证据

- 留存真实桌面开关对照、动态更新、四向圆角、暂停／恢复和宿主重建的截图或录屏，以及业务检查日志、旧配置兼容和重启记录。
- 离屏渲染可辅助核对前景和布局，不作为后方画面已被模糊的唯一证据。动态壁纸若未在真实环境验证，应明确标为未验证。
- 本规格不声称当前已验证任何毛玻璃效果或硬件场景。不得将其他功能的历史单屏验收结果扩大为本功能或多屏验收结论。
- 精确性能阈值、支持环境范围与最终模糊强度需要在前置验证和实际验收中记录；不得补写未经测量的数值或无证据的支持承诺。

## 范围外（Out of Scope）

- 模糊强度滑块、逐 Folder 强度设置、多种毛玻璃预设或其他背景材质选项。
- 全局开关、批量应用、修改新建 Folder 的默认启用策略。
- 单独设置头部与展示部分的毛玻璃开关、颜色或强度。
- 动态壁纸播放器、壁纸管理、桌面图标样式或操作方式的改造。
- 背景功能引起的自动移动、尺寸改变、布局算法调整及文件内容修改。
- 完全重做样式窗口、额外通知入口、托盘快捷开关或发布流程变更。
- 用静态壁纸快照代替已确认的实时后方画面；这不属于本规格授权的降级效果，降级应回到现有背景。

### 平台资料

以下资料用于说明方案需要验证的边界，不构成可行性证明：

- Microsoft 明确说明 `DwmEnableBlurBehindWindow` 仅适用于顶层窗口，且 Windows 8 起调用不再产生模糊。当前 Explorer 桌面子窗口不能直接采用该旧 API 作为已证明方案。[DwmEnableBlurBehindWindow](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmenableblurbehindwindow)

- Microsoft Acrylic 文档说明系统透明效果、省电和高对比度会影响材质显示，背景 Acrylic 在失去焦点时也可能使用纯色。本规格要求失去焦点后仍持续显示，因此需验证具体方案是否满足该行为。[Acrylic material](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)
