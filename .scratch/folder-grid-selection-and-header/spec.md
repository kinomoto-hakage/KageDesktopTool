## 问题陈述（Problem Statement）

用户切换 Folder 网格中的小、中、大图标时，图标间距没有随尺寸明显变化，名称空间不足，选中被省略的名称后仍无法完整阅读。当前格子受到系统网格下限约束，小、中档可能共用同一格子尺寸。

不同 Folder 独立维护图标选择，点击桌面、其他 Folder 或切换应用后，之前的选中状态可能继续保留，造成操作对象不明确。

头部目前固定在展示部分上方，展示部分只能向下展开。用户希望根据桌面空间把头部放在上、下、左、右，并独立切换 Folder 名称横排和竖排，同时保留已有尺寸、最近空位、样式预览及重启恢复能力。

## 解决方案（Solution）

网格的小、中、大、超大四档分别调整格子宽高和间距，优先保留横向名称空间。未选中的名称最多显示三行，超出后使用末尾省略号。选中时，只有单选项或多选中的最后操作项展开完整名称，图标及其他格子位置保持固定。

完整名称在所属 Folder 的展示部分内显示，允许暂时遮住下方项目，通过滚动整个内容区域阅读超出视口的部分。必要时增加内容滚动范围，不改变 Folder 尺寸，不显示到 Folder 外，也不因名称展开触发最近空位计算。展开文字的点击、双击和右键均归属当前选中项。

统一协调所有 Folder 的选择。点击桌面非 Folder 区域、任意 Folder 头部、普通左击或右击 Folder 空白、点击任务栏或切换到其他应用时，清除已有选择。操作另一个 Folder 时先清除之前 Folder 的选择。当前 Folder 的 Ctrl／Shift 多选、滚动和图标原生右键菜单操作继续保留选择。

每个 Folder 独立设置并保存头部位置和名称方向，默认上方头部、横排名称。上、下、左、右头部分别向下、上、右、左展开展示部分。名称竖排时字符保持正向，逐个从上往下排列；名称空间不足时省略，悬停显示完整 Folder 名称。

四向布局以头部左上角为桌面锚点。切换到侧边头部时保留展示部分的宽高，侧栏高度跟随展示部分高度。尺寸手柄跟随方向，样式窗口实时预览，应用保存，取消恢复原样式、尺寸和位置。空间不足时只移动当前 Folder；无合法空位时展开保持折叠，样式修改保留上一个可用布局并提示。

## 用户故事（User Stories）

1. 作为用户，我希望小、中、大、超大网格图标都有适配自身尺寸的格子宽高，以便切换尺寸时得到相应的排列密度。
2. 作为用户，我希望各档图标间距实际随尺寸改变，以便小、中档不会因共同的系统网格下限而看起来完全相同。
3. 作为用户，我希望同一档的格子尺寸和间距一致，以便图标排列整齐且容易点击。
4. 作为用户，我希望网格优先给名称留足横向空间，以便尽量减少名称省略。
5. 作为用户，我希望未选中名称最多显示三行，以便兼顾名称可读性和网格密度。
6. 作为用户，我希望超过三行的名称使用末尾省略号，以便知道还有未显示的内容。
7. 作为用户，我希望较短名称完整显示，以便不出现无必要的省略。
8. 作为用户，我希望切换网格尺寸后列数按可用宽度重新计算，以便格子完整排列在展示部分内。
9. 作为用户，我希望列表视图保持现有布局，以便本次网格优化不改变列表使用习惯。
10. 作为用户，我希望四档图标和文字在不同 DPI 下清晰且正确命中，以便视觉位置与实际点击一致。
11. 作为用户，我希望选中被省略的图标名称后展开完整文字，以便确认操作对象。
12. 作为用户，我希望选中后展开名称不会移动该图标或其他图标，以便保持原网格间距和排列位置。
13. 作为用户，我希望多选时只展开最后点击项的名称，以便多个长名称不会同时遮挡内容。
14. 作为用户，我希望通过键盘定位到选中项时也更新完整名称的展示对象，以便鼠标和键盘行为一致。
15. 作为用户，我希望其他多选项继续保持三行显示，以便仍能辨认选择集合。
16. 作为用户，我希望完整名称始终留在所属 Folder 内，以便不遮住其他 Folder 或桌面区域。
17. 作为用户，我希望完整名称超出可见区域时滚动整个 Folder 内容即可继续阅读，以便无需操作单独的名称滚动框。
18. 作为用户，我希望长名称所需的额外滚动范围不会改变 Folder 尺寸，以便布局保持稳定。
19. 作为用户，我希望展开名称时允许临时覆盖下方项目，以便在图标不挪动的前提下阅读全文。
20. 作为用户，我希望展开名称的点击归属当前项，以便不会误选文字下面的图标。
21. 作为用户，我希望双击展开名称仍打开当前项，以便名称与图标拥有相同的打开行为。
22. 作为用户，我希望右击展开名称仍操作当前选择集合，以便保留原生文件菜单和多选操作。
23. 作为用户，我希望取消选择后名称恢复最多三行且被遮住的项目恢复可见与可操作，以便继续浏览内容。
24. 作为用户，我希望选中长名称时仅做必要滚动，让图标和名称开头可见，以便随后自行阅读其余部分。
25. 作为用户，我希望滚动阅读全文期间保持选择，以便名称不会中途收起。
26. 作为用户，我希望取消选择后保留当前滚动位置，以便不会突然跳回原位置。
27. 作为用户，我希望额外滚动范围收起后只在当前位置超出有效范围时回退到新的末端，以便避免无必要的跳动。
28. 作为用户，我希望名称展开不移动任何 Folder，也不参与 Folder 最近空位计算，以便其他桌面布局保持稳定。
29. 作为用户，我希望点击桌面非 Folder 区域时清除之前 Folder 的选择，以便选择状态符合当前操作位置。
30. 作为用户，我希望点击任意 Folder 头部时清除已有图标选择，以便头部操作与文件操作对象明确。
31. 作为用户，我希望普通左击任意 Folder 空白时清除所有 Folder 的选择，以便不用逐个取消。
32. 作为用户，我希望右击任意 Folder 空白时同样清除图标选择，以便随后操作 Folder 菜单时不混淆对象。
33. 作为用户，我希望操作另一个 Folder 的图标时先清除之前 Folder 的选择，以便同时只有当前操作的 Folder 持有选择。
34. 作为用户，我希望跨 Folder 按 Ctrl／Shift 操作也清除之前 Folder 的选择，以便多选不会跨多个内容区域累积。
35. 作为用户，我希望当前 Folder 的 Ctrl 点击仍能切换选中状态，以便修改当前多选集合。
36. 作为用户，我希望当前 Folder 的 Shift 连选和 Ctrl／Shift 框选保持现有规则，以便继续使用熟悉的批量选择操作。
37. 作为用户，我希望点击任务栏时清除 Folder 的选择，以便离开桌面操作后不留下选中反馈。
38. 作为用户，我希望切换到其他应用时清除 Folder 的选择，以便返回桌面时看到明确的初始状态。
39. 作为用户，我希望滚轮滚动和操作当前 Folder 滚动条时保留选择，以便查看已选内容。
40. 作为用户，我希望打开和操作当前图标的原生右键菜单期间保留选择，以便菜单命令作用于正确的项目集合。
41. 作为用户，我希望点击菜单以外的桌面、任务栏或其他应用时清除选择，以便退出菜单后的状态与外部点击规则一致。
42. 作为用户，我希望普通内容刷新仍按项目身份保留有效选择，以便无外部点击时不会意外丢失选择。
43. 作为用户，我希望取消选择后普通刷新不会恢复已经清除的选择，以便状态保持一致。
44. 作为用户，我希望文件拖动和原生菜单仍使用正确的选择集合，以便新增选择协调不破坏批量操作。
45. 作为用户，我希望每个 Folder 可独立选择上、下、左、右头部位置，以便适应不同桌面空间。
46. 作为用户，我希望上方头部向下展开，以便保持现有使用方式。
47. 作为用户，我希望下方头部向上展开，以便把入口放在桌面下侧。
48. 作为用户，我希望左侧头部向右展开，以便利用桌面横向空间。
49. 作为用户，我希望右侧头部向左展开，以便从右侧入口查看内容。
50. 作为用户，我希望折叠时按钮指向展开方向、展开时指向收起方向，以便从按钮识别动作。
51. 作为用户，我希望折叠后仅显示头部且保持头部位置，以便入口不会随展示部分收起而跳动。
52. 作为用户，我希望展开、折叠及切换方向时优先保持头部左上角的桌面位置，以便固定入口。
53. 作为用户，我希望从上／下头部切换到侧边头部时保留展示部分宽高，以便内容不会因宽高交换而重新变成另一种形状。
54. 作为用户，我希望侧栏高度跟随展示部分高度，以便头部与展示部分边缘对齐。
55. 作为用户，我希望切换头部位置后图标和展示部分文字仍正向显示，以便不会旋转内容。
56. 作为用户，我希望每个 Folder 独立选择名称横排或竖排，以便按头部形状安排文字。
57. 作为用户，我希望名称方向与头部位置独立组合，以便四个位置都可选横排或竖排。
58. 作为用户，我希望名称默认横排，以便已有 Folder 和新 Folder 保持熟悉的阅读方式。
59. 作为用户，我希望竖排时每个中文字符保持正向、从上往下排列，以便直接阅读。
60. 作为用户，我希望竖排时英文和数字同样逐字符正向排列，以便混合名称有统一规则。
61. 作为用户，我希望横排和竖排名称在空间不足时都使用省略，以便不挤出其他头部控件。
62. 作为用户，我希望鼠标悬停显示完整 Folder 名称，以便在头部省略时仍能确认名称。
63. 作为用户，我希望侧栏名称在上、文件数在下、展开按钮在底端，以便沿竖向找到这些信息。
64. 作为用户，我希望侧栏文件数保持横排，以便快速阅读数字。
65. 作为用户，我希望上／下头部保留现有名称、文件数和按钮横向排列，以便保持现有习惯。
66. 作为用户，我希望左右侧栏可独立调宽，以便横排名称拥有合适空间。
67. 作为用户，我希望分隔线在上／下头部通过上下拖动调整厚度，在左／右头部通过左右拖动调整厚度，以便手势符合视觉方向。
68. 作为用户，我希望展示部分远离头部的外角调整展示部分宽高，以便四个方向都能调整内容空间。
69. 作为用户，我希望折叠时可以调整头部长度和厚度，以便不必展开就能调整入口。
70. 作为用户，我希望折叠时头部长度变化同步影响下次展开时与头部相接的展示边长，以便展开后边缘仍对齐。
71. 作为用户，我希望尺寸调整优先保持头部位置，以便调整不会无故挪动入口。
72. 作为用户，我希望空间冲突时只移动当前 Folder 到最近合法空位，以便其他 Folder 的位置、尺寸和展开状态保持不变。
73. 作为用户，我希望展开没有合法空位时保持折叠并说明原因，以便不会出现越界或重叠。
74. 作为用户，我希望布局继续避开任务栏、其他 Folder 和显示器之间的空洞，以便内容可见且可操作。
75. 作为用户，我希望从现有“样式”窗口调整头部位置和名称方向，以便集中管理同一 Folder 的外观。
76. 作为用户，我希望设置变化实时预览，以便应用前看到实际效果。
77. 作为用户，我希望“应用”保存当前有效样式和布局，以便重启恢复。
78. 作为用户，我希望“取消”恢复打开窗口前的样式、尺寸和位置，以便撤销包括自动寻找空位产生的移动。
79. 作为用户，我希望预览方向或侧栏宽度找不到合法空位时保留上一个可用布局并提示，以便继续选择其他设置。
80. 作为用户，我希望未生效的预览修改不会被应用保存，以便设置与实际显示一致。
81. 作为用户，我希望保存失败时原配置保持有效，并可以重试或取消，以便不会留下半套已提交设置。
82. 作为用户，我希望已有配置缺少新增字段时仍按上方头部、横排名称和原尺寸恢复，以便平滑升级。
83. 作为用户，我希望不同 Folder 的方向和尺寸独立保存与恢复，以便不会修改其他 Folder。
84. 作为用户，我希望升级保留内容文件夹、查看方式、排序和原有外观设置，以便现有整理结果持续可用。
85. 作为用户，我希望真实鼠标、键盘、系统菜单和应用切换经过实际 Windows 会话验证，以便验收覆盖我实际使用的交互路径。

## 实现决策（Implementation Decisions）

- **测试边界与职责**：沿用 `IDesktopWorkspace` 作为布局、查看设置、样式会话、状态提交和恢复的最高业务边界。渲染、瞬时选择、桌面命中及前台切换由现有桌面应用协调，Windows 平台能力留在平台适配层。实际可见结果通过已有 Windows 端到端输入验收，不为检查新增公开的测试专用业务入口。
- **网格度量**：修改内容展示度量，统一计算图标、三行名称区域、格子宽高和间距。四档必须产生可观察的格子和图标间距变化，不能继续被同一系统网格下限锁成相同布局。保留系统标题字体与 DPI 信息作为度量输入；不规定一套未经实际渲染验证的固定像素常量。布局以完整格子计算列数、命中和框选边界，列表布局不在本次调整范围内。
- **完整名称与滚动**：未选中名称的三行高度属于固定格子；完整名称展示不参与格子重排。仅当前选中的最后操作项展开，必须位于所属展示视口内，与内容一起滚动，并按全文的实际末端扩展滚动范围。不能通过增加 Folder 高度、改变其他格子尺寸或在 Folder 外显示文字解决边界问题。完整文字位于被遮挡项之上，命中归属当前项，操作沿用现有打开与原生菜单流程。
- **滚动状态**：选中时只做一次必要可见性调整，显示图标及名称开头；不在用户继续滚动时反复拉回。取消选择、切换展开对象或收起额外范围时保留当前偏移，仅在超出有效范围时夹到新的末端。滚动不触发清除选择。
- **选择协调**：各 Folder 共用应用层选择协调规则，统一处理当前操作 Folder、选中集合与完整名称展示对象；选择属于瞬时交互状态，不增加磁盘持久化。明确区分应清除的外部点击／应用切换与应保留的当前滚动、Ctrl／Shift 多选和当前图标原生菜单。清除后同步取消完整名称和陈旧的连选锚点，后续刷新不得恢复已清除的选择。
- **现有输入约束**：保留真实双击、修饰键、框选、身份刷新、内部自定义重排和跨 Folder／桌面／Explorer 的实际文件移动。外部检测不能把滚动或当前图标原生菜单的临时前台变化误判成切换应用，也不能破坏已开始的拖动操作所使用的文件集合。选择清除不得吞掉系统原本应收到的点击。
- **头部与名称配置**：Folder 记录新增独立的头部位置和名称方向。位置四档与方向两档允许八种组合。已有记录缺少字段时使用上方、横排，新建记录也使用该默认值。名称竖排按用户可见字符逐个正向排列，避免拆坏组合字符；英文和数字不旋转、不整段横放。横排、竖排均支持省略和完整名称悬停提示。
- **几何模型**：统一以头部左上角表示桌面锚点，按位置、厚度及展示部分宽高计算整个 Folder 的边界；下方／右侧头部展开时，窗口原点与头部锚点分离，不能直接复用窗口左上角。持久化结构必须能独立表达展示部分宽高及头部厚度，旧尺寸按原上方头部几何解释，不交换宽高或丢失原位置。
- **方向与排列**：上、下、左、右分别向下、上、右、左展开。折叠按钮指向展开方向，展开按钮指向收起方向。上／下头部采用现有横向控件排列；左／右头部采用名称在上、横排文件数在下、按钮底端的排列。侧栏的头部长度随展示部分高度，上／下头部长度随展示部分宽度；名称方向只改变名称排版，不旋转展示部分或其他控件。
- **四向尺寸交互**：头身分隔线沿垂直于连接边的方向调整头部厚度，不改变展示部分宽高；展示部分远端外角调整其宽高；折叠时调整头部长度和厚度，长度更新相接的展示边长。按当前目标 DPI 将真实鼠标位移换算为 DIP，复用预览、释放提交及取消语义。侧栏厚度须允许有效的独立调宽，不能不加评估地沿用仅适用于顶部高度的固定范围。
- **位置与合法性**：位置仍采用物理屏幕坐标，尺寸仍采用 DIP，保留既有布局间隙、工作区并集约束及最近空位稳定选取规则。四向的整个可见边界参与越界、碰撞和显示器选择，目标锚点采用头部位置。当前位置合法时保留，否则只移动当前 Folder，不修改其他 Folder 的位置、尺寸或展开状态。无展开空间时保持折叠；无有效设置预览空间时拒绝该次修改并保持上一个有效草稿。
- **显示环境与拖动**：沿用跨屏 DPI 选择、无自洽解时的头部原点屏回退，以及自由拖动预览可穿越其他 Folder、释放才寻找合法空位的行为。新增四向边界应与这些规则共用几何计算，不能在 UI、业务和恢复流程中各自推算一套尺寸。
- **样式会话**：在已有外观草稿／应用／取消流程上扩展方向、名称排版和相关几何预览。草稿独立于已提交状态，实时预览期间不写正式配置。方向变化产生的最近空位移动属于该草稿，取消时一并恢复。应用一次提交当前有效外观与布局；失败时保留原正式状态，允许重试或取消。沿用既有过期会话、工作区恢复锁定及显示变化校验，不能用旧草稿覆盖后来的合法状态。
- **兼容与领域语义**：旧配置默认值保留原顶部布局、内容映射、原尺寸及其他设置。实现时同步调整领域文档中“展示部分固定在头部下方”的描述；本文已批准的四向模型替代该方位限制。原规格中系统网格作为固定下限的要求，以本次四档可观察变化和三行名称规则为准；最近空位与真实文件操作的既有约束继续适用。

## 测试决策（Testing Decisions）

- **好测试的标准**：检查正式入口触发后的用户可见行为、实际窗口边界、命中目标、选择集合、真实文件效果和保存／重启结果。不要只断言某个内部常量、方法被调用或控件已声明某个属性，也不要以直接设置选中状态或注入 WPF 事件代替真实交互验收。
- **业务先例**：复用现有工作区检查中的内容查看、布局、升级布局、显示／DPI、外观、保存失败和隔离状态仓库模式。通过 `IDesktopWorkspace` 验证四向状态转换、样式草稿、提交／取消、其他 Folder 不变及旧状态恢复。
- **Windows 先例**：复用现有真实内容输入、内容布局、布局输入、外观和显示 DPI 检查中的临时目录、真实文件／快捷方式、桌面宿主、系统鼠标／键盘输入与窗口截图证据。新增或扩展这些正式路径的检查，不以仅有业务模型通过替代实际渲染、命中或焦点检测。

| 验证范围 | 必须覆盖的外部结果 |
| --- | --- |
| 四档网格 | 固定 Folder 尺寸下依次切换小、中、大、超大；测量真实格子、图标边缘间隔和列数，确认档位变化；短名称完整，长名称最多三行且末尾省略；列表布局回归。 |
| 完整名称 | 单选及多选最后点击／键盘定位；固定其他格子位置；选中最下行超长名称后滚动能读到末尾；文字始终被所属视口裁剪，Folder 和其他 Folder 几何不变。 |
| 名称命中 | 展开名称暂时覆盖下方项目时，真实点击、双击和右键作用于当前项；取消后下方项目恢复命中，原生多选菜单仍针对正确集合。 |
| 滚动恢复 | 选中仅做必要可见性调整；滚轮及滚动条保留选择；取消／换项后保留有效偏移，超界才夹到末端，不反复滚回图标。 |
| 全局清除 | 至少两个 Folder，通过真实输入分别点击桌面空白／桌面项目、不同头部、不同空白、其他 Folder 图标、任务栏，并真实切换应用；验证旧选择与完整名称立即清除，系统点击正常送达。 |
| 选择保留与回归 | 当前 Folder 的 Ctrl／Shift 点击、框选、连选、滚动、右键已选项及菜单操作；跨 Folder 修饰键不累积选择；正常身份刷新保留有效选择，已清除的选择不复活；拖动文件集合和实际移动正确。 |
| 四向几何 | 四种头部位置的展开／折叠、按钮方向、头部锚点稳定、窗口原点与头部位置不同的下／右情况；上下与侧边相互切换保持展示部分宽高；其他 Folder 不变。 |
| 八种名称组合 | 四位置乘横排／竖排；中文、英文、数字及组合字符；省略和真实悬停全文；侧栏文件数横排及按钮可见、可命中。 |
| 四向缩放 | 展开分隔线厚度、展示远端外角宽高、折叠头部长度／厚度；正确拖动方向、相接边长同步、DPI 位移换算、取消与保存结果。 |
| 空间与失败 | 当前位置可用、占用落点、贴近四边、无空位、负坐标、显示器空洞和任务栏；最近合法位置只影响当前 Folder；无空间展开保持折叠，无效样式修改保留上一有效布局并提示。 |
| 样式事务 | 打开前记录原样式及几何，预览方向／名称／尺寸和自动挪位，应用后重启恢复；取消及关闭恢复原状态；无效修改不保存；保存失败和过期会话不覆盖有效状态。 |
| 升级恢复 | 用真实旧配置缺省新增字段初始化并重启；保留位置、尺寸、内容目录、列表／网格、各自图标尺寸、排序及颜色透明度；新配置逐 Folder 恢复四向及名称方向。 |

- **夹具与证据**：使用唯一随机的临时工作区、真实内容目录和可辨认的打开结果；Windows 桌面／焦点／原生菜单检查串行运行，避免相互抢焦点。只清理所属夹具，保留截图、实际窗口矩形、输入步骤及状态前后对比。
- **硬件声明**：业务显示轨迹可覆盖负坐标、上下／左右跨屏和混合 DPI；实际多显示器、混合 DPI、拔屏、主屏或系统缩放变化只有在对应硬件会话中完成才算真实验证。未覆盖项明确列出，不以注入度量或历史单屏结果代替。
- **本次发布状态**：当前只发布规格，未修改应用实现，未运行功能验收；上述内容是实现阶段必须完成的验证计划。

## 范围外（Out of Scope）

- 修改列表视图布局、增加新的图标尺寸档位或提供独立的用户间距编辑器。
- 同时展开多个选中项的完整名称、在 Folder 外显示图标名称或给名称增加单独滚动框。
- 因图标名称展开而改变 Folder 尺寸、移动图标或触发 Folder 布局放置。
- 跨多个 Folder 保留多选集合，或把选中状态作为重启恢复配置。
- 将竖排名称整行旋转、把英文数字作为整段横排，或旋转展示部分。
- 为满足当前 Folder 的展开或调整而自动挪动其他 Folder，或在无空间时自动交换展示宽高、缩小内容区域、折叠已展开 Folder。
- 修改文件移动、存储根目录迁移、回收站、托盘图标或通知等已有功能的产品行为。
- 本次规格发布直接实施功能、生成发布包或宣称真实硬件验收已通过。
