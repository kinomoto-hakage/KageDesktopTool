# 13: 中断后恢复迁移并定位未恢复的真实内容

Type: implementation
Status: superseded-draft
Spec: ../../spec.md
Blocked by: 12
User stories: 58–59, 25

**实现内容（What to build）：** 迁移中断或恢复不完整后，用户重新启动程序，看到实际路径、未完成清单和恢复入口，可定位内容并重试恢复；程序不盲目重复移动或按错误根目录展示。

**阻塞关系（Blocked by）：** 12「更换存储根目录、整体迁移并处理当场失败和取消」产生可持久的逐项操作记录及恢复结果。

## 验收标准

- [ ] 启动先检查未完成记录，核对实际目录和快捷方式状态，再决定恢复／显示状态，不直接套用旧或新全局路径。
- [ ] 在执行前、部分目录完成、快捷方式更新、配置提交及恢复中断等阶段退出后重启，都能判断实际执行结果。
- [ ] 恢复不完整时显示实际路径和未恢复项目，能打开现有内容位置并重试恢复；禁止不知情的路径修改继续扩大不一致。
- [ ] 重复启动或重复恢复不重复覆盖、复制或删除已经处理的内容，稳定标识及活动／保留状态正确。
- [ ] 恢复到旧根目录及对应快捷方式目标后退出恢复状态；仍失败时保留可定位的证据，不伪造正常工作区。
- [ ] 通过共用操作 interface 和真实临时目录验证进程级中断／重新打开、逐项故障及恢复失败，检查字节内容和路径而非仅检查日志存在。

## 来源与交付检查

- 演示：迁移部分完成时退出 → 重启看到恢复状态 → 打开实际内容 → 重试恢复 → 工作区重新一致。
