# 修复网格居中与列表缩放布局

Type: bug
Status: resolved

## 用户反馈

- 网格文件项中，图标没有相对完整选择区域居中，项间距不协调；希望采用原生桌面排列逻辑。
- 列表加宽 Folder 后左侧留白增加；希望左侧固定，只改变右侧，并使用原生列表的高度和密度。
- 用户同时确认上一项拖动卡顿修复已通过人工检查。

## 复现

通过 `--view-regression` 对实际 WPF 内容执行测量和排列：

- 图标相对完整网格项中心的检查失败。
- 不刷新内容、直接从 300 DIP 加宽到 460 DIP 后，左侧图标移动了 80 DIP，检查失败。

检查不创建交互窗口，使用随机命名的两文件夹具，完成后校验其位于原型内容目录内再清理。

## 原因与修复

- 旧网格内容按其自身期望宽度排布，图标与文字的对齐没有参考完整文件项。改用占满统一格子的 Grid，将图标和标题居中。
- 旧列表项在刷新时保存固定宽度；窗口后续加宽时，该宽度没有更新，项目会在新增空间中偏移。取消固定宽度，使用随视口伸缩的行和靠左的图标列。
- 移除随意设置的 90／38 DIP 最小高度及较大的项内间距。网格读取系统图标网格尺寸；列表通过隐藏原生 ListView 测量行高，并使用系统图标标题字体。

## 验证

- 构建通过，0 个错误、0 个警告。
- 网格中心检查通过。
- 列表加宽时图标左侧偏移为 0 DIP；反复缩窄／加宽检查通过。
- 当前交互会话 150% 缩放下：系统网格 113 × 113 像素，原生小图标列表行高 26 像素；程序按 DPI 转为 WPF 布局单位。
- 新网格、列表及加宽预览已检查；已有拖动回归继续通过。
- 新运行入口：`prototypes/DesktopFolderPrototype/bin/LayoutFix/DesktopFolderPrototype.exe`。
