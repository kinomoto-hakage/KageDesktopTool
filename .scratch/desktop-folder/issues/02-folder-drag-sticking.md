# 修复 Folder 接触边界后的拖动停滞

Type: bug
Status: resolved

## 问题

按住头部拖动 Folder，接触屏幕四边或另一个 Folder 后，继续拖动再反向，会出现不跟手的停滞；同时无法沿接触面滑动。

## 确定性复现

命令：

```powershell
rtk proxy dotnet prototypes/DesktopFolderPrototype/bin/DragFix/DesktopFolderPrototype.dll --drag-regression --minimal
```

最小轨迹通过与真实鼠标事件共享的拖动入口重放：在左侧边界继续向外拖 80 像素，再反向 1 像素。修复前 Folder 实际移动 0 像素，检查失败；修复后移动 1 像素，检查通过。

完整轨迹最初发现 12 项失败。单独修复锚点后，立即反向检查通过，仍有 6 项沿边滑动检查失败，从而区分两项原因。

## 原因

1. 拖动以按下时的鼠标和窗口位置作为固定锚点；非法位置被拒绝后，受阻的鼠标位移继续累积，反向时必须先偿还这段距离。
2. 二维目标只要有一个方向碰撞，就拒绝整次移动；合法的切向位移也被丢弃。

最小重放不依赖窗口绘制，且采用屏幕像素坐标，所以绘制耗时或 DPI 不是该停滞的主因。

## 修复

- 每次鼠标输入都更新锚点，以相邻输入的屏幕像素差推动当前位置。
- 投影到可用屏幕区域，分别限制受阻方向，允许沿接触面滑动。
- 沿移动路径限制其他 Folder 的碰撞，保持现有间距和不重叠约束。
- 丢失鼠标捕获时结束拖动，避免沿用过期锚点。
- 保留无交互窗口的回归入口；新程序输出到独立的 `bin/DragFix/`，避免覆盖正在试用的旧版。

- 最小复现通过。
- 完整回归通过：屏幕四边贴边、即时反向及沿边滑动；折叠和展开 Folder 的四向碰撞与不重叠。
- 回归检查不修改内容文件、持久状态或正在运行的旧版。
