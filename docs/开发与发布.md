# 开发与发布

本文供源码维护者使用。软件的日常操作见[仓库首页](../README.md)和[完整使用说明](使用说明.md)。

## 源码运行

需要 Windows 与 .NET 10 SDK。在仓库根目录双击 `run.cmd`，或执行：

```powershell
rtk proxy dotnet restore src/KageDesktopTool/KageDesktopTool.csproj --configfile NuGet.Config
rtk proxy dotnet run --project src/KageDesktopTool/KageDesktopTool.csproj --no-restore
```

## 构建与验证

业务检查与界面共用 `IDesktopWorkspace`，使用随机隔离目录。正式图标位于 `src/KageDesktopTool/Assets/`；修改 WPF 图像资源后使用 Rebuild 验证。

```powershell
rtk proxy dotnet restore tests/Kage.Workspace.Checks/Kage.Workspace.Checks.csproj --configfile NuGet.Config
rtk proxy dotnet run --project tests/Kage.Workspace.Checks --no-restore
rtk proxy dotnet build src/KageDesktopTool/KageDesktopTool.csproj -c Release -t:Rebuild
```

Windows 输入、Shell、回收站及桌面恢复检查需在当前用户的交互式 Windows 会话串行执行。具体命令与覆盖范围见[1.1.0 发布验收记录](verification/upgrade-05-upgrade-and-release.md)，单项检查可用 `verify-release.ps1 -OnlyCheck <名称>`。

## 生成发布包

`publish.ps1` 从项目读取版本，使用 Windows x64 自包含发布配置，生成完整目录、ZIP、逐文件 `SHA256SUMS.txt` 和 ZIP 的 SHA256。构建需从 NuGet 获取运行时包；已有发布目录会被拒绝覆盖。

```powershell
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File publish.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File verify-release.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File verify-archive.ps1
rtk proxy powershell -NoProfile -ExecutionPolicy Bypass -File verify-user-launch.ps1
```

默认目录为 `releases/KageDesktopTool-win-x64-<项目版本>/`。已有同版本产物时，发布需指定新的 `-OutputDirectory releases/<新目录>`，验收脚本则传入相同的 `-PackageDirectory`。

组合验收会操作鼠标、托盘和 Explorer，执行时需留出输入；普通启动验收要求已有实例退出、实际用户状态可用且无待恢复操作。检查通过仅代表所记录的实际环境与覆盖范围。

## 维护文件

- `src/Kage.Workspace/`：业务接口、状态存储和真实目录操作。
- `src/KageDesktopTool/`：WPF、桌面宿主、托盘、热键及 Windows 适配。
- `tests/`：业务回归；`tools/`：图标生成器、发布共用函数和系统菜单修复工具。
- `.scratch/`：本地规格与票据；`docs/verification/`：验收结论。部分历史临时日志、截图及旧包已清理，复现时需重新准备。
- `releases/`、构建缓存和隔离验收产物忽略 Git；发布 ZIP 需单独提供下载。

系统菜单修复的本机还原资料位于 `.scratch/windows-shell-latency/final-backup-v2/`，使用前阅读[故障诊断与恢复说明](verification/windows-lnk-menu-delay.md)。
